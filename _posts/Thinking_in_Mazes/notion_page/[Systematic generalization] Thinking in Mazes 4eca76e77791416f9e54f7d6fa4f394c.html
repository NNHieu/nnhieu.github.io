[Systematic generalization] Thinking in Mazes

Introduction

When a human solves a small maze, they don't just recite the exact twists and turns from memorization; they use spatial search strategies. When faced with a novel or larger maze, they easily extend those very same search techniques to solve it simply by spending more time. In traditional computer science, this is achieved through the use of algorithms, which encode a process that scales to arbitrarily hard problem instances at the cost of more computation. Standard feed-forward neural networks, however, lack this flexibility. Their computing budget is strictly limited by their pre-defined architecture (such as depth and width, … ). A feed-forward network trained on a simple 9×9 maze has no built-in mechanism to "think longer" to accommodate a harder 13×13 maze.

This limitation is challenged by the paper "Can You Learn an Algorithm? Generalizing from Easy to Hard Problems with Recurrent Networks". The authors demonstrate that recurrent networks—specifically weight-tied convolutional neural networks—trained to solve simple problems with few recurrent steps can indeed solve much more complex problems simply by performing additional recurrences during inference. They generalize not by adding parameters, but by extending their iteration budget.

But a fascinating question remains: What exactly is the network doing during these extra iterations? Has it learned a classical pathfinding algorithm like Breadth-First Search, or has it discovered a completely different mechanism native to the geometry of convolution?

In this post, we will open the black box. By visualizing the internal activations of a weight-tied CNN at each iteration, we can observe the network's reasoning process in real-time. What we find is a dynamic, localized algorithm based on morphological pruning—a process where the network actively explores paths while simultaneously collapsing dead-ends using learned, scale-invariant rules.

This blog explores how a fixed-point neural network behaves on maze-solving tasks, highlighting the model’s iterative update process, where it succeeds or fails, and what changes when recurrence, input injection, or different solvers are used.

Preliminary

To understand how these networks learn an algorithm, we first need to establish the rules of the environment and the structure of the model.

The Maze Environment

The task is visual maze solving. The network is fed a two-dimensional $N\times N$ image of a maze where the walls are represented as black pixels, and the start and goal locations are indicated by distinct colors (e.g., red and green).

The objective is not to output a single coordinate, but dense pixel-wise segmentation. The label for each maze is a binary two-dimensional mask containing the locations of positions along the shortest path solution. The network outputs logits for each pixel, which are thresholded to create a predicted binary path. To measure true algorithmic success, a candidate solution is only considered correct if it exactly predicts the labeled, continuous path from start to finish.

The critical element of this setup is the concept of "easy" versus "hard." The authors formalize this by training models exclusively on datasets of smaller mazes (e.g., $9\times9$) and testing their logical extrapolation behaviors on larger mazes (e.g., $13\times13$).

Weight-tied CNN

The architectures utilized are based heavily on standard ResNets. To isolate the effect of recurrence, the authors keep the structural comparisons as close as possible.

  • Feed-Forward ResNet: A standard deep network where each residual block possesses its own unique set of learned weights. Information flows linearly from input to output.
  • Recurrent ResNet: The recurrent models are identical, except that all residual blocks share weights. We refer to this shared block as the recurrent module.
  • Recurrent ResNet with input injection:

An "iteration" simply represents one forward pass through this recurrent module. During training on small mazes, the number of iterations is fixed (e.g., 20 iterations). Because the weights are tied, the recurrent module's input and output dimensions are identical, allowing the output of step $t$ to be fed directly back in as the input for step $t+1$.

mThis structural loop is what enables the "algorithmic" behavior. Instead of the weights acting as static feature extractors, the shared weights act as a localized transition rule that is applied iteratively to the feature map. When evaluating a harder $13\times13$ maze at test time, we don't need to rebuild the network; we simply allow the recurrent module to loop for more iterations than it did during training.
